产品规划文档 v1.0

文本提取浏览器插件

面向付费内容平台，绕过 CSS 复制限制，精准提取正文，本地保存为 TXT

目标平台：Chrome MV3 / Edge
核心交互：点击 DOM 块选择
AI 策略：三层分级识别
开发周期：MVP 约 2–3 周

一、核心问题与解法

付费内容平台通过 CSS user-select: none 或 JS 拦截事件阻止复制，但文字实际存在于 DOM 中。插件通过 element.innerText 直接读取文本节点，完全绕过前端限制。

🔒

限制机制

CSS user-select、JS mousedown 拦截、右键菜单禁用

✂️

突破方式

content script 读取 innerText，不触发任何 UI 事件

🎯

精准提取

用户手动点选目标块，结合 AI 自动识别正文区域

💾

本地保存

页面标题命名，一键下载 TXT，无需任何云端存储

二、AI 正文识别 · 三层分级架构

AI 能力不是用来"找到正文在哪里"，而是分层降级，每层各司其职。用户最终的操作始终是主导，AI 负责减少手动操作量。

层级
职责与触发时机
覆盖率
第一层
Readability.js
自动识别正文区域（默认启动）
插件激活时，Mozilla Readability.js 自动解析页面，提取主文章容器，高亮显示推荐区域。用户只需确认，不需要手动点击。离线运行，零延迟，零成本，无隐私风险。
~90%
第二层
手动点选
用户精确指定（Readability 失败时）
第一层识别结果不满意时，用户进入手动模式：悬停段落自动高亮，点击锁定，支持多块叠加。这是产品核心交互，始终可用，不依赖任何外部服务。
100%
第三层
云端 LLM
AI 清洗提炼（用户选中后可选触发）
对已选中的少量文本进行：去除版权声明/广告语、合并破碎段落、格式化输出。发送给 API 的是精简后的文本片段（非整页 HTML），隐私风险和 token 成本均可控。用户自填 API Key，插件不中转。
可选

第三层 API 调用设计原则

最小数据原则

只发送用户已选中的文本，不发送 HTML 结构、页面 URL 或 Cookie 信息

用户自主 API Key

用户在设置页填入自己的 Key，直接调用 Anthropic/OpenAI，插件不做任何中转

明确提示词

Prompt 固定为"清理格式，去除广告词，保留原文内容"，不让模型二次创作

四、核心交互流程

1

访问目标页面，点击插件图标

页面顶部出现蓝色提示条「选择模式已开启」，Readability.js 后台解析正文

2

自动推荐正文区域

Readability 识别成功：主文章容器出现蓝色虚线框 + 提示「已识别正文，点击接受」

⚡ 90% 的页面到这里就完成了
3

手动补充或修正（可选）

用户不满意时，点击「手动选择」，鼠标悬停高亮段落，点击锁定；可在自动识别结果上叠加选择

4

预览与编辑

右侧面板展示所有已选文本，支持删除某块、调整顺序；底部显示字数统计

5

可选：AI 清洗

点击「AI 清洗」触发 API 调用（需预先填入 Key），去除广告语和版权声明，格式化段落；结果显示在面板供确认

6

保存下载

点击「保存 TXT」，弹出浏览器下载框，文件名：《页面标题》_20240515_1430.txt

五、TXT 文件格式规范

六、技术选型

插件平台
Chrome Extension MV3
现代标准，兼容 Edge；MV3 Service Worker 替代 Background Page
正文识别
@mozilla/readability
npm 可安装，Firefox 阅读模式内核，单文件引入，覆盖率 ~90%
内容脚本
content_script.js (原生 JS)
无框架依赖，注入体积小；Shadow DOM 隔离插件样式
面板 UI
popup.html + sidebar panel
popup 做控制，侧边 panel 做预览，chrome.sidePanel API
本地存储
chrome.storage.local
暂存已选内容；API Key 用 AES 加密后再存储
文件下载
chrome.downloads API
Blob URL 生成 TXT，触发浏览器原生下载
AI 清洗
Anthropic / OpenAI API
用户自填 Key，直连 API，插件不做中转；模型建议 claude-haiku / gpt-4o-mini（低成本）
动态内容
MutationObserver
监听 DOM 变化，适配无限滚动/懒加载页面

七、风险与应对

⚠️
Canvas / 图片渲染的文字
部分平台用 Canvas 把文字渲染成图像，innerText 无法读取。应对：检测到 Canvas 时提示用户切换截图 + OCR 方式，或引导使用印象笔记 Clipper 等工具，不强行尝试
⚠️
Shadow DOM 内容
Web Components 渲染的正文 innerText 无法穿透。应对：在 content script 中递归检查 shadowRoot，读取 shadowRoot.innerText
⚠️
插件样式被页面覆盖
高优先级 CSS 会破坏高亮效果。应对：使用 Shadow DOM 隔离插件注入的 UI 元素；高亮样式用极高 z-index + !important
⚠️
平台反插件检测
少数平台检测 user-select 是否被修改，可能触发封号风险。应对：插件只读取文本，不修改 CSS 属性，降低被检测概率；产品定位明确聚焦个人学习笔记
💡
API Key 安全
用户 Key 存在 chrome.storage.local 中有泄露风险。应对：使用 AES-GCM 加密存储，Key 从不出现在请求日志或 popup 的可见文本中

八、开发路线（推荐顺序）

  • MutationObserver 支持动态内容
